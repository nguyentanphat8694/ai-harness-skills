## Modules and units

- **Module** = one business capability (Customers, Sales, Inventory, Receivables, Reporting, System & Permissions). Name it by business meaning, never by technical folder. Module code: 2-5 uppercase letters (`KH`, `SAL`, `SYS`).
- **Unit** = the smallest thing that carries requirements; belongs to exactly one module.

| Type | Prefix | Examples |
|---|---|---|
| Screen (Form/Dialog) | `SCR` | `frmCustomer`, `frmLogin` |
| Shared component (UserControl, base form, UI helper) | `CMP` | `ucAddressPicker`, `frmBase` |
| Service / business logic (BLL, Service) | `SVC` | `OrderBLL`, `PricingService` |
| Report / printing | `RPT` | `rptDeliveryNote` |
| Background / scheduled job | `JOB` | sync timer, backup |
| DB object with logic (SP, trigger, view, function) | `DB` | `sp_CalcStock` |
| External integration (printer, scale, COM, file, email, API, device) | `INT` | barcode reader, mail sender |

Unit ID: `<TYPE>-<MODULE>-<ShortName>`, e.g. `SCR-KH-List`, `SVC-SAL-Pricing`. `ShortName` is ASCII PascalCase and unique within a module; put localized names/captions in `aliases`.

Granularity: one unit = one form, one class/function group serving one business purpose, one report, or one SP. Do not make a unit per method. A DAL/Repository class that only wraps CRUD has no unit: record its queries in the calling unit's "Data access" section. Tiny helpers without business meaning (logging, string formatting) go to `CMP-SHARED-Utilities`; a helper with a formula or rule becomes an FN inside its owning `SVC` unit.

A unit used by several modules is owned by one module (or `_SHARED`); others reference it by unit ID and never copy its content.

## Output directory layout

```
requirements-docs/
├── STATE.json            single source of truth: status, rev, hashes, ID counters, inventory
├── INDEX.md              human view, GENERATED by scripts/state.py index (never hand-edit)
├── APP-OVERVIEW.md       app purpose, tech stack, architecture, actors, module map, coverage
├── NAVIGATION.md         entry point, startup flow, menu tree -> screens, screen-to-screen flows
├── DATA-MODEL.md         tables/entities, keys, relations, status columns, who reads/writes what
├── ROLES-MATRIX.md       role x screen/function permission matrix and where it is enforced
├── CONFIG-AND-INTEGRATIONS.md  app.config/settings keys, environments, 3rd-party libs, devices, external systems
├── WORKFLOWS.md          end-to-end business flows that cross modules (by unit ID)
├── FUNCTIONS.md          catalogue of FN (auto-calculated / auto-filled / derived fields)
├── IMPROVEMENTS.md       IMP: flaws in the legacy app + suggestions + acceptance status
├── OPEN-QUESTIONS.md     open questions pointing back to owning unit
├── GLOSSARY.md           domain terms, abbreviations, legacy variable names
├── CHANGELOG.md          log of added/changed/dropped requirements, discrepancies, source drift
├── SRS.md                final consolidated document (built in the synthesis phase)
├── screenshots/          optional: UI images the user supplied, named by unit ID
└── modules/
    ├── <MODULE>/
    │   ├── MODULE.md
    │   └── units/<UNIT-ID>.md
    └── _SHARED/
```

Templates for every file are in `assets/templates/`.

## Naming rules

- **Root**: `requirements-docs/` next to the source, or where the user says. Stored once in `STATE.json` (`root`); never create a second copy.
- File/folder names are ASCII, no spaces. Fixed names exactly as above; no variants (`INDEX-v2.md`).
- Unit file name equals the unit ID.
- Content (titles, descriptions) is written in the documentation language (default English; see `doc_language` in STATE). Keep original class, method, table, column names and original message strings verbatim, in code font, for traceability; give a translation next to non-English UI strings.

## ID formats

IDs are ASCII with a 3-digit sequence; counters live in STATE and are allocated with `scripts/state.py next-id`.

- Requirement: `REQ-<MODULE>-<ShortName>-<nnn>` (from unit `SCR-SAN-Exam` -> `REQ-SAN-Exam-001`)
- Business rule `BR-<MODULE>-<nnn>`; function `FN-<MODULE>-<nnn>`; improvement `IMP-<MODULE>-<nnn>`; open question `Q-<nnn>` (project-wide)
- Shared content uses module `SHARED` (`BR-SHARED-001`).
- IDs are never reused or renumbered, even for DROPPED items.
